# Learning Agent Platform Product Spec

## 1. 项目愿景

Learning Agent Platform 是一个长期演进的复杂产品，目标是把“编程学习网站”“个人 AI Agent 软件端”和“Skill 社区”组合成一个连续的学习与自动化系统。

用户不只是阅读编程书籍，而是在一个能理解书籍内容、理解学习进度、理解用户能力变化的环境中学习。AI 不只是回答问题，而是逐步形成用户画像、推荐练习、记录表现，并在软件端总结用户反复做的工作，沉淀为可复用 Skill。

最终形态是：

- 用户在网站中阅读、提问、练习、导入资料、获得个性化学习路线。
- 用户在软件端和 AI 协作完成日常任务，AI 能生成和运行 Skill。
- 用户可以从社区下载、审查、安装 Skill，让自己的 AI 获得更多能力。
- 系统在安全权限、记忆压缩、工具调用、任务日志和自主性控制下长期稳定运行。

本项目必须分阶段小步开发，不能一次性实现全部系统。

## 2. 目标用户

### 2.1 编程学习用户

- 正在学习编程基础、Web 开发、算法、AI 工程、系统设计等内容的学生或自学者。
- 阅读技术书籍时经常遇到理解断点，需要结合上下文解释。
- 希望系统根据自己的真实能力推荐每日练习，而不是固定题库。

### 2.2 高强度工具使用者

- 经常让 AI 帮忙处理重复性任务的用户。
- 希望 AI 能从对话和操作历史中总结重复工作，并生成可复用 Skill。
- 需要可控的自主性，不希望 AI 未经允许执行高风险操作。

### 2.3 Skill 创作者和社区用户

- 愿意制作、分享、下载、改造 Skill 的用户。
- 希望 Skill 在安装前能看到风险等级、工具需求、权限需求和安全说明。
- 需要一个既开放又有审查机制的 Skill 生态。

## 3. 用户痛点

### 3.1 学习侧痛点

- 技术书籍内容密集，用户读到一半不理解时，普通聊天 AI 不知道当前书籍和章节上下文。
- 学习进度、错题、能力短板分散，系统无法持续追踪用户能力。
- 每日题单经常固定化，无法根据用户最近表现动态调整。
- 许多有价值资料来自网页、PDF、Markdown、长文本，导入后缺少章节结构和阅读体验。

### 3.2 Agent 侧痛点

- AI 经常重复执行相似任务，但不会自动沉淀为可复用能力。
- 用户难以控制 AI 到底能不能执行命令、写文件、调用工具或后台运行任务。
- 长对话中的重要记忆容易丢失，历史任务无法高效检索。
- 后台任务执行过程不透明，失败原因和风险边界不清晰。

### 3.3 Skill 社区痛点

- 外部 Skill 质量和安全风险不透明。
- 用户下载 Skill 前不知道它会调用什么工具、需要什么权限、能做哪些写入操作。
- 社区 Skill 如果默认自动执行，会引入严重安全风险。

## 4. 核心价值

- 上下文感知学习：AI 回答问题时结合当前书籍、章节、段落、用户进度、历史表现和能力分数。
- 个性化练习：系统根据能力模型和学习行为生成每日题单。
- 任意资料可学习化：用户导入文本或网页后，系统自动解析、切分、生成章节结构。
- 可控 AI Agent：用户可配置从“只回答”到“高自主性”的权限模式。
- Skill 自动沉淀：软件端从用户反复任务中总结、生成、复用 Skill。
- 安全 Skill 生态：社区 Skill 安装前必须展示风险、工具、权限和安全说明，默认不可自动执行。

## 5. 编程学习网站功能

### 5.1 书籍库

- 展示系统内置或用户导入的编程书籍。
- 支持按语言、主题、难度、进度筛选。
- 每本书维护元信息：标题、作者、来源、标签、难度、章节列表、导入状态。

### 5.2 在线阅读器

- 支持章节导航、阅读进度记录、内容高亮和当前位置追踪。
- 阅读器需要提供“向 AI 提问”的入口。
- 提问时自动携带当前书籍、当前章节、当前选中文本、附近上下文和用户学习状态。

### 5.3 学习问答

- AI 回答必须基于可用上下文，不应假装知道未导入或未索引内容。
- 回答应能解释概念、给出代码示例、指出与前文的关系、推荐下一步练习。
- 对于超出当前资料范围的问题，需要明确说明依据和不确定性。

### 5.4 用户能力模型

- 记录用户阅读进度、问题类型、答题表现、复习情况、题目正确率、提示使用情况。
- 维护多个维度的能力分数，例如语言基础、调试能力、算法理解、工程实践、系统设计。
- 能力分数应可解释，不能只是一个黑盒总分。

### 5.5 每日题单

- 根据用户能力分数、最近学习章节、错题历史和目标方向生成每日题单。
- 题单应包含难度梯度：巩固题、提升题、挑战题。
- 系统记录题单完成情况，并反向更新能力模型。

### 5.6 书籍导入

- 用户可以导入纯文本、Markdown、网页内容或手动粘贴内容。
- 系统需要生成导入任务，记录解析状态、失败原因和重试入口。
- 初期可以只支持文本和 Markdown，网页导入放在后续阶段。

### 5.7 自动章节生成与内容切分

- 系统根据标题、编号、语义边界和长度限制生成章节结构。
- 对长章节进行 chunk 切分，用于检索、阅读定位和 AI 问答。
- 章节生成结果需要允许用户后续校正。

## 6. AI 软件端功能

### 6.1 对话入口

- 用户可以像普通 AI 客户端一样对话。
- 对话支持上下文记忆、任务状态、工具调用状态和 Skill 推荐。

### 6.2 自主性设置

至少支持以下模式：

- 只回答，不执行：AI 只能给出建议和说明。
- 执行前必须确认：任何工具调用或写入都需要用户确认。
- 自动执行低风险只读任务：允许读取、搜索、分析等低风险操作。
- 自动执行低风险写入任务：允许在限定范围内创建或修改低风险文件。
- 高自主性模式：允许较高程度自动执行，但高风险任务仍需确认。

### 6.3 后台工具调用

- 支持任务排队、执行、取消、重试和状态查询。
- 所有工具调用必须记录工具名、输入摘要、输出摘要、风险级别、触发来源和执行结果。
- 高风险工具调用必须有确认记录。

### 6.4 任务执行日志

- 每个任务需要完整生命周期：创建、等待、运行、需要确认、成功、失败、取消。
- 日志用于用户审计、调试失败、生成 Skill 和改进推荐。

### 6.5 记忆压缩

- 长对话需要分层压缩，保留长期事实、近期任务、用户偏好和重要决策。
- 压缩后的记忆必须可追溯到来源对话或任务日志。
- 记忆不应无限增长，需要有保留策略和过期策略。

### 6.6 记忆检索

- AI 在回答或执行任务前，可以检索相关历史对话、任务、Skill 使用记录和用户偏好。
- 检索结果需要按相关性、时间和可信度排序。

### 6.7 Skill 生成

- 系统根据重复任务候选生成 Skill 草案。
- Skill 草案至少包含用途、触发条件、输入参数、执行步骤、所需工具、权限等级、风险说明和测试样例。
- Skill 生成后不能默认启用自动执行，必须经过用户确认。

### 6.8 Skill 运行

- Skill 运行需要检查权限、自主性等级和工具可用性。
- 运行过程必须产生任务日志。
- Skill 失败时需要提供可理解的失败原因和恢复建议。

## 7. Skill 社区功能

### 7.1 Skill 浏览

- 用户可以查看社区 Skill 列表、分类、评分、下载量、作者和更新时间。
- 支持按工具需求、风险等级、适用场景筛选。

### 7.2 Skill 详情页

安装前必须展示：

- Skill 名称、作者、版本、用途说明。
- 所需工具和外部能力。
- 所需自主性等级。
- 风险等级。
- 可能读取或写入的数据范围。
- 安全说明和用户授权要求。

### 7.3 Skill 安装

- 社区 Skill 默认不可自动执行。
- 用户必须审查并授权后才能安装。
- 安装后仍需遵守本地自主性设置和权限判断。

### 7.4 Skill 审查与更新

- Skill 更新需要展示变更摘要和新增权限。
- 新增工具、新增写入能力或风险等级提高时必须重新授权。

## 8. MVP 范围

MVP 目标是打通最小闭环，而不是完成全部愿景。

### 8.1 学习网站 MVP

- 基础书籍列表。
- 单本书的章节阅读。
- 当前章节内 AI 问答。
- 简单用户进度记录。
- 简单能力分数模型。
- 基于能力分数和章节的每日题单原型。
- 文本或 Markdown 导入。
- 基础章节识别和 chunk 切分。

### 8.2 AI 软件端 MVP

- 基础对话 UI。
- 自主性设置页面。
- 只读工具调用原型。
- 任务执行日志。
- 简单记忆摘要。
- 手动创建和运行本地 Skill。

### 8.3 Skill 社区 MVP

- 本地或模拟社区 Skill 列表。
- Skill 详情页。
- 安装前风险展示。
- 安装后手动运行。

## 9. 非 MVP 范围

以下内容不在 MVP 中实现：

- 大规模真实社区、支付、作者收益分成。
- 完整浏览器插件生态。
- 多租户企业管理。
- 复杂社交系统。
- 高级自动评测平台。
- 多模型自动路由优化。
- 完整 PDF/OCR/视频课程导入。
- 完全自动生成高质量题库。
- 高自主性 Agent 的所有能力。
- 跨设备实时同步。

## 10. 后续增强方向

- 更强的书籍解析：PDF、EPUB、网页抓取、代码块识别、目录校正。
- 更强的能力模型：知识图谱、遗忘曲线、概念掌握度、跨书籍迁移。
- 更强的题单系统：动态难度、错题复习、项目式练习、面试路线。
- 更强的 Agent：后台长任务、工具编排、低模型任务执行、计划修正。
- 更强的 Skill：自动发现重复任务、生成 Skill、测试 Skill、发布 Skill。
- 更强的安全：权限沙箱、风险评分、审查报告、用户授权审计。
- 更强的社区：版本管理、评分、举报、精选、作者主页。

## 11. 产品开发原则

- 先做可运行闭环，再做规模化和智能化。
- 每个阶段只解决一个主问题。
- 所有 AI 能力都必须有失败路径和可解释状态。
- 所有自动执行能力都必须经过权限判断。
- 所有社区 Skill 都必须默认保守，不能默认自动运行。
- 后续 Codex 会话必须小步开发，不允许一次性实现整个系统。

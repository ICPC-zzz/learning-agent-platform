# AI Native Learning Platform Direction

## 1. 一句话产品定位

Learning Agent Platform 的网页端重新定位为面向编程学习者和算法竞赛学习者的 AI Native 学习平台：通过每日技术热点、GitHub 开源项目日报、专题学习资源和 Codeforces 个性化训练，为用户提供“获取信息 -> 学习知识 -> 制定训练 -> 完成题目 -> 复盘提升”的连续学习体验。

## 2. 目标用户

- 正在系统学习编程、软件工程、AI 工程或算法竞赛的学生和自学者。
- 希望每天用较少时间筛选技术信息、开源项目和学习资料的开发者。
- 使用 Codeforces 训练算法能力，但缺少稳定题单、复盘和弱点跟踪的用户。
- 需要 AI 帮助解释技术热点、拆解项目价值、生成训练计划和做代码复盘的学习者。

## 3. 核心用户问题

- 技术信息来源分散，用户不知道每天真正值得看什么。
- GitHub Trending、博客、社区文章数量很大，但缺少面向学习目标的筛选和中文解释。
- Codeforces 题库足够丰富，但用户难以根据 rating、标签、失败记录和目标难度生成合理题单。
- 普通 AI 聊天无法持续记录用户训练表现，也无法解释为什么推荐某道题或某篇资料。
- 旧的“大而全 OJ / 自建判题 / 多 OJ 抓取”方向成本高、合规风险高，且不直接提升学习闭环。

## 4. 三条核心能力

### 4.1 技术内容与行业信息

文章中心不再只是普通文章聚合，而是内容学习入口，包含：

- 每日技术热点。
- GitHub 日报。
- 精选技术文章。
- 针对用户薄弱点推荐的学习资料。
- 与用户近期训练目标相关的专题内容。

文章中心的核心问题是：“今天值得看什么，以及为什么值得看。”

### 4.2 Codeforces 题目资源中心

题目中心近期只使用 Codeforces 官方 API，不追求同时接入大量 OJ，不建设自有 OJ，不复制第三方完整题面。

题目中心的主要用途是：

- 为 Agent 提供候选题池。
- 支持按 rating 和标签筛选题目。
- 支持专题训练。
- 支持每日个性化题单。
- 支持用户训练记录和复盘。

近期题目业务字段限定为：

- 题目名称 `name`。
- 题目 rating `rating`。
- 题目标签 `tags`。

底层可以保留去重、更新和跳转所需的技术标识，例如 `contestId`、`index`、来源标识 `Codeforces` 和原题链接字段。这些字段只用于基础设施，不代表导入完整题面。

明确不导入：

- 完整题面。
- 输入说明。
- 输出说明。
- 样例。
- 官方题解全文。
- 第三方翻译题面。
- VJudge 题面。
- 用户提交代码作为公共题目数据。

### 4.3 网页端 AI 学习 Agent

AI Agent 不再规划为无边界聊天框，而是网页端学习助手：

- 每日学习与训练规划助手。
- 技术热点和 GitHub 日报解读助手。
- Codeforces 个性化组题助手。
- 分层提示教练。
- 代码与解题复盘助手。
- 周期训练调整助手。

所有 Agent、工具调用、Skill、自主性能力仍必须优先考虑权限、日志和安全边界。近期不把 Agent 做成可任意执行工具的万能助手。

## 5. 内容中心结构

### 5.1 每日技术热点

每日技术热点用于帮助用户快速了解编程、软件开发和 AI 领域的重要变化。规划内容可包括：

- AI 与 Agent 技术。
- 编程语言和开发框架。
- 后端、前端、数据库和云原生。
- 开源工具。
- 开发者工具。
- 算法竞赛和计算机教育。
- 重要软件版本与生态变化。
- 对普通开发者真正有影响的技术事件。

每条热点至少包含：

- 标题。
- 中文摘要。
- 来源。
- 原始链接。
- 发布时间。
- 主题分类。
- 重要程度。
- 为什么值得关注。
- 与用户兴趣或学习方向的关联。

近期只规划产品流程、数据边界和实现阶段，不在文档轮实现抓取代码。

### 5.2 GitHub 日报

GitHub 日报不是简单复制 GitHub Trending，而是帮助用户理解：

- 今天有哪些值得注意的新项目。
- 哪些已有项目增长明显。
- 哪些项目发布了重要版本。
- 哪些 AI、Agent、开发工具或编程学习项目值得关注。
- 项目解决什么问题。
- 是否值得学习、试用或加入自己的工具链。

每条日报记录可包含：

- 仓库名称。
- 仓库简介。
- 主要编程语言。
- Star、Fork 等公开指标。
- 最近增长或活跃趋势。
- 最近 Release。
- 项目分类。
- 仓库链接。
- 中文摘要。
- 推荐理由。
- 适合哪些用户。
- 学习成本或使用门槛。
- 与用户技术方向的关联。

数据源优先规划为 GitHub 官方 API、仓库公开信息、GitHub Releases 和合法可用的公开趋势来源。不得批量复制 README 全文，不得无来源编造摘要，不得把 Star 数量作为唯一推荐标准。

### 5.3 专题学习资源

现有技术文章、书籍、章节和阅读器能力继续保留，但职责调整为：

- 支持热点相关背景学习。
- 支持 GitHub 项目相关技术学习。
- 支持 Codeforces 弱点补课。
- 支持 Agent 推荐用户当前最需要阅读的内容。
- 将阅读记录纳入用户长期学习上下文。

## 6. 产品核心闭环

训练闭环：

1. 获取用户信息和 Codeforces 训练记录。
2. 判断当前水平与薄弱点。
3. 从 Codeforces 候选题池中筛选题目。
4. 生成少量且有解释的每日题单。
5. 用户在原 Codeforces 页面完成题目。
6. 使用分层提示和代码复盘。
7. 更新用户学习状态。
8. 调整下一次题单和学习资料。

内容闭环：

1. 汇总每日技术热点和 GitHub 日报。
2. 根据用户兴趣和训练方向排序。
3. 推荐值得阅读的热点或项目。
4. 必要时关联专题学习资源。
5. 将阅读和收藏信号写入用户学习上下文。

## 7. MVP 范围

Web MVP 包括：

1. 每日技术热点基础展示。
2. GitHub 日报基础展示。
3. Codeforces 题目名称、rating 和标签同步。
4. Codeforces 题目搜索与筛选。
5. 用户 Codeforces handle 和目标设置。
6. 基础训练诊断。
7. 每日少量个性化题单。
8. 推荐原因。
9. 分层提示。
10. 解题结果记录。
11. 代码或过程复盘。
12. 下一阶段计划调整。
13. 相关文章推荐。

MVP 不包括：

- 自建 OJ。
- Docker 判题。
- 完整题面同步。
- 样例同步。
- 多 OJ 扩张。
- Skill 商店。
- 大型社区。
- 万能 AI Agent。

## 8. 后续阶段

1. 文档和旧范围收口。
2. Codeforces 最小题目数据源。
3. 用户训练档案。
4. 每日个性化题单 MVP。
5. 分层提示与解题复盘。
6. 每日技术热点。
7. GitHub 日报。
8. 文章、热点、题单和 Agent 联动。
9. 周期总结与动态调整。
10. 真实用户验证。

核心闭环验证成功后，才考虑更多 OJ、Desktop 深度联动和 Skill 社区。

## 9. 产品指标

训练指标：

- 每日题单开始率。
- 每日题单完成率。
- 连续训练天数。
- 推荐题重复率。
- 分层提示使用层级。
- 复盘完成率。
- 相同标签独立完成率变化。
- 提示依赖是否下降。
- 用户是否主动查看下一日题单。

内容指标：

- 每日热点打开率。
- 热点原文跳转率。
- GitHub 日报打开率。
- 仓库链接跳转率。
- 用户收藏或稍后阅读比例。
- Agent 个性化推荐点击率。
- 热点和 GitHub 日报次日回访率。

反向信号：

- 用户只浏览题库，不使用题单。
- 用户只跳转原题，不记录结果。
- AI 仍然只是普通聊天框。
- GitHub 日报只是机械复制排行榜。
- 每日热点来源不透明。
- 资源数量增加，但连续使用没有提高。
- 用户认为直接使用 ChatGPT、GitHub Trending 或 Codeforces 更方便。

## 10. 风险和假设

- 内容数据源必须合法、可追溯、可去重，不复制第三方全文。
- Codeforces 题目只保存最小元数据和原题跳转，不复刻题面。
- 初期训练诊断优先使用可解释规则和简单统计，不构建黑盒评分模型。
- Agent 建议必须能解释依据，不能伪造用户训练状态或外部数据。
- 旧 Docker Judge、自建 OJ、VJudge 完整题面导入方向需要标记为废弃或暂停，避免后续继续投入。

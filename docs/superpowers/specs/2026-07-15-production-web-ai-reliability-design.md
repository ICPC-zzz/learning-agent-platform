# 生产 Web AI 可靠性修复设计

日期：2026-07-15

## 背景与根因

生产站点的 AI 助手在写入长期记忆后继续普通问答时显示：
`Web AI dev guard is blocked because NODE_ENV is production.`

取证结果表明：

- 服务器运行在 `NODE_ENV=production`。
- 正式模型配置完整，`LAP_ALLOW_PRODUCTION_WEB_AI=true` 与 `LAP_ALLOW_REAL_LLM=true` 均已显式开启。
- `evaluateWebAiQaGuard` 仍沿用开发预览阶段的逻辑，只要是生产环境就无条件加入 `production_only`。
- “记住……”走确定性的长期记忆写入分支，不调用模型，因此第一轮可以成功；后续普通问答才进入模型守卫并失败。
- 守卫内部英文诊断被作为助手消息和页面错误直接返回，还被持久化到会话历史。
- 代码分析已经能识别部署前后 Server Action 标识不一致并自动刷新，但普通对话没有使用该恢复逻辑。生产日志已经出现 `Failed to find Server Action`。
- AI 对话状态在浏览器初始化时预先生成随机会话 ID。服务端把不存在的指定 ID 当作新会话创建，导致每次重新进入页面都可能新增一条空会话。
- 后台状态采集只传入旧的开发变量，没有完整读取正式模型变量，可能继续错误显示模型状态。
- 生产反向代理下，受保护路由使用内部请求地址构造登录跳转，导致未登录访问 `/ai` 或 `/user` 时被重定向到 `https://localhost:3000`，而不是公开域名。

## 目标

- 正式模型仅在生产双重授权和完整配置同时满足时可调用。
- 普通问答、训练计划、旧版多 Agent 汇总和后台记忆整理必须共用同一个生产守卫，用户自定义模型也不能绕过全局关闭开关。
- 开发环境继续保持显式开启，不能因本次修复被默认放开。
- 用户页面只显示中文、安全、可操作的错误，不暴露内部变量、守卫名称或 Provider 诊断。
- 普通 AI 对话在部署切换造成 Server Action 协议不匹配时自动刷新恢复。
- 重新进入 AI 页面优先恢复最近活跃会话，不再创建空白会话。
- 后台模型状态使用与实际调用相同的配置快照。
- 受保护路由使用经过校验的 `APP_BASE_URL` 构造公开登录地址，避免泄露反向代理内部主机名。
- 通过单元、源码契约、类型检查、生产构建和线上冒烟验证闭环。

## 非目标

- 不重构完整 Agent、工具或多 Agent 架构。
- 不删除用户现有会话，包括已经产生的空会话。
- 不修改模型提示词、学习建议内容或 Codeforces 推荐算法。
- 不无条件开放生产模型调用。
- 不在服务器执行依赖安装或生产构建。

## 方案

### 1. 将 Web AI 守卫升级为双模式正式守卫

`evaluateWebAiQaGuard` 返回三种模式：

- `blocked`
- `external_dev`
- `external_production`

开发模式必须满足现有开发开关、模型配置和非生产环境条件。

生产模式必须同时满足：

- `NODE_ENV=production`
- `LAP_ALLOW_PRODUCTION_WEB_AI=true`
- `LAP_ALLOW_REAL_LLM=true`
- 助手、外部调用和 LLM 均已启用
- Provider、地址、认证材料和模型均完整

任何条件缺失都 fail closed。生产失败时对普通用户只返回统一中文提示；具体缺失项保留在安全结构化状态中，供后台状态页和服务端日志使用，不作为聊天正文。

所有直接创建 Provider 的路径也必须先通过该守卫，包括可靠 Agent Loop、旧版结果汇总和后台记忆候选提取。`LAP_LLM_ENABLED=false` 具有最高关闭语义，即使其他授权为 true 也不得调用模型。

### 2. 区分用户文案与内部诊断

守卫的 `notice` 改为可公开中文文案。普通聊天面板不再把内部英文诊断作为助手正文。Provider 调用失败（包括已有工具结果的降级分支）统一返回通用中文提示，内部错误只使用稳定错误码记录。

历史会话中已经存在的英文消息不自动改写，避免未经允许修改用户数据；新请求不会再写入该内容。

### 3. 统一 Server Action 部署恢复

把现有恢复提示从“重新提交代码分析”改为通用 AI 操作提示。普通对话至少覆盖以下异步入口：

- 初始会话加载
- 发送消息
- 新建、切换、归档、删除和压缩会话
- 手动刷新会话列表

识别到 Next.js 部署版本不匹配后显示中文提示，并进行一次页面刷新。取消任务、重试步骤和重试任务同样覆盖。普通业务错误不得误判为部署问题。

### 4. 修复空会话创建

客户端初始 `conversationId` 改为空字符串，表示“没有指定会话”。服务端 `getOrCreateConversation` 在未指定 ID 时恢复最近活跃会话，仅在用户没有任何活跃会话时创建第一条会话。

用户明确点击“新建会话”仍调用服务端创建接口。客户端重置状态同样回到未指定会话，不生成一个服务端可能持久化的伪 ID。

### 5. 修正后台状态采集

后台状态采集直接使用完整的 `createAssistantProviderEnvSnapshot`，确保正式变量、兼容变量和实际 AI 调用读取一致。页面仍不显示密钥值。

### 6. 修正生产登录跳转来源

中间件优先读取并校验 `APP_BASE_URL`：生产环境只接受无用户名和密码、且不是 localhost/回环地址的 HTTPS 地址；开发环境允许 HTTP。生产配置缺失或无效时返回 503，不再回退到内部请求来源。这样生产反向代理的内部地址不会出现在用户跳转链接中。

## 安全边界

- 生产调用需要两个独立的显式授权开关，任一缺失即拒绝。
- 地址继续只允许 HTTPS 或本机 HTTP。
- API Key、密码、原始 Prompt 和原始响应不进入客户端诊断。
- 不扩展现有工具执行权限。
- 本轮不会自动删除或改写会话数据。

## 测试与验收

### 自动化测试

- 生产环境缺少任一生产授权时守卫拒绝。
- 全局 LLM 开关关闭时，所有直接 Provider 路径均拒绝调用。
- 生产双重授权且配置完整时返回 `external_production`。
- 开发配置继续返回 `external_dev`。
- 生产拒绝提示为中文且不包含 `NODE_ENV`、`dev guard` 或密钥名称。
- AI 普通对话源码接入部署恢复逻辑。
- 初始会话 ID 为空，页面重新挂载不会用随机指定 ID 创建空会话。
- 后台状态采集使用完整 Provider 环境快照。
- 生产受保护路由的登录跳转使用公开 HTTPS 来源，不出现 `localhost`。
- Provider 失败及工具降级分支只返回中文安全文案。
- 既有会话仓库、认证和部署恢复测试继续通过。

### 生产验收

- 精确部署 GitHub 已推送提交。
- `https://cfagent.fun/api/health` 返回 HTTP 200。
- 未登录访问 `/ai` 与 `/user` 均跳转到 `https://cfagent.fun/auth/login`，并保留安全的 `returnTo`。
- 登录用户发送普通学习建议问题能得到模型回复，不再出现开发守卫英文错误。
- 连续第二轮对话成功，长期记忆仍可读取。
- 进入 AI 页面前后空会话数量不增加。
- 服务日志没有新的守卫拦截和未处理 Server Action 错误。
- 当前 release Git 提交与 GitHub `origin/main` 一致。

## 回滚

- 原子切回上一 release 并重启 Web 服务。
- 不修改数据库 schema，不需要数据回滚。
- 新增环境变量协议兼容当前服务器；回滚代码后原有变量保留不会影响其他服务。

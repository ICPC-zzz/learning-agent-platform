# 个性化代码分析并行化设计

## 目标

保留现有题目画像提示词和 Rating 结果质量，同时避免题目画像模型调用的耗时阻塞代码分析模型调用。

## 方案

A492 在完成输入校验后，同时启动题目画像与代码分析。题目画像仍然使用现有 `profileProblem` 实现和提示词；代码分析仍然使用现有 `runCodeAnalysisWorkflow`、超时和输出限制。两条任务各自捕获异常并降级，最终聚合时等待两者结果：题目画像失败时使用现有规则画像，代码分析失败时保留其他画像数据并显示代码分析失败状态。

为便于回归测试，编排器依赖增加一个可选的代码分析执行器，生产环境默认使用现有工作流，测试可以注入确定性的短任务。事件顺序仍使用已有事件类型，允许两个并行任务按实际完成顺序写入完成事件，不改变最终报告结构。

## 边界与风险

- 不修改任何模型提示词。
- 不增加新的 Provider、工具执行权限或后台持久化任务。
- 不把代码分析结果注入题目画像，也不把题目画像注入代码分析提示词。
- 并行请求可能增加 Provider 瞬时并发，但题目画像已有短超时和输出上限；若画像调用失败，代码分析仍独立完成。

## 验收

- 回归测试证明慢题目画像尚未完成时，代码分析已经启动并可以完成。
- 回归测试证明题目画像最终结果仍会进入聚合报告。
- 相关测试、ai-core typecheck 和 web typecheck 通过。
